# 지켜야 할 규칙

「두 개의 항로」는 학생 기기에서 서버 없이 돌고, 출판사에 납품되며, 1차시에 받아 적은 이어 하기 글자로 2차시를 잇는다. 그래서 이 게임에서는 어기면 점검이 실패하거나, 납품이 막히거나, 학생의 저장·이어 하기 글자가 깨지는 규칙만 지킨다.

## 형태와 의존

- 게임은 HTML + CSS + 순수 JavaScript다. 빌드 도구·번들러·프레임워크·npm 런타임 의존을 들이지 않는다. 위반: `index.html`이 빌드 산출물을 부르거나, 게임 코드가 `import`/`require`/CDN 스크립트를 쓰는 것. 그리기는 Canvas 2D와 CSS, 소리는 Web Audio다(Three.js 등 3D 엔진은 쓰지 않는다).
- npm 의존은 `tests/`의 `playwright` 하나뿐이다. 게임 폴더 뿌리에는 `package.json`이 없다.
- 실행 중 외부로 나가는 요청을 만들지 않는다. 위반: `js/`·`css/`·`index.html`에 `http(s)://` 주소로 실제 요청하는 `src`·`href`·`fetch`·`@import`가 생기는 것(SVG 이름공간 문자열은 예외).
- 모든 경로는 상대 경로다. 공개 주소·하위 주소·도메인을 코드에 넣지 않는다. 위반: `/assets/…`처럼 `/`로 시작하는 경로, 배포 주소가 박힌 og 메타·manifest. `index.html`을 파일로 열어도(`file://`) 시작·저장이 되어야 한다(`tests/file.mjs`).
- 새 스크립트 파일은 `index.html`에 `<script>`로 등록하고, 엔진 → 게임 → 데이터 → 거점 → `main.js` 차례 안의 제자리에 둔다. `tests/content.mjs`가 이 차례대로 실으므로 등록하지 않은 파일은 점검에서도 빠진다.
- 형제 저장소(`../영웅소설`, `../관동별곡` 등 시리즈의 다른 게임)와 예전 복사본 `../최척전`은 읽기만 한다. 이 저장소의 작업은 `choecheok-jeon`에서만 한다.

## 데이터와 엔진의 나눔

- 이야기 글·대사·선택지·카드·맵·목표·조정 숫자는 `js/data/`에만 둔다. 위반: `js/core/`·`js/game/`에 줄거리 문장이나 딜레마·카드 문안이 새로 들어가는 것(엔진의 대체 글 — '준비 중', 기본 단추 이름 — 은 예외).
- 엔진은 거점 id·딜레마 id를 하드코딩하지 않고 규칙 표(`TEXTS.RULES`의 `act1`·`act2`·`trail`·`interlude`·`prepDilemma`·`routeDilemma`)와 거점 자료를 읽는다. 예외는 이어 하기 글자의 부호표(`js/game/code.js`의 `LAYOUT`)뿐이다.
- 생성 구역은 손으로 고치지 않는다.
  - `js/data/sprites.js` 전체: `tools/process_sprites.py`가 쓴다.
  - `js/data/people.js`의 `// ART:BEGIN` ~ `// ART:END`: `tools/process_assets.py`가 `assets/sc`·`assets/pt`의 실제 파일로 다시 쓴다.
  - `js/data/bgm.js`의 `tongso:` 한 줄: `tools/make_tongso.py`가 바꾼다.
- 새 단계 종류는 그 화면을 맡은 `js/game/` 파일에서 `G.steps.register`로 등록한다. 거점 자료가 부르는 모든 단계 종류는 등록되어 있어야 한다(`tests/content.mjs`: '준비 중' 0).
- 새 저장 칸은 `G.save.extend({ 이름: 처음 값 })`으로 더하고, 단계 도중 새로고침 때 되돌려야 하는 칸이면 `G.save.snapKeys`에 넣는다. `localStorage`를 직접 읽고 쓰는 곳은 `js/core/save.js` 하나다.

## 이어 하기 글자와 저장의 호환

이미 나누어 준 이어 하기 글자와 학생 기기의 진행이 깨지지 않게 하는 구조 규칙이다(글자는 1막의 선택·지식·횟수만 담고 나머지는 1막 단계를 같은 규칙으로 다시 흘려 계산한다).

- `js/game/code.js`의 `LAYOUT`(딜레마 셋과 선택지 수 2·3·2, 지식 여섯의 차례, 함정 A·B·C, 더듬기 0~10, 고친 횟수 0~8)과 글자판·섞음 값·검사식을 바꾸지 않는다. 바꾸면 이미 받은 글자가 거절되거나 다른 상태로 되살아난다.
- 1막 딜레마 셋(`d-namwon-flee`, `d-nanggoya-news`, `d-nanggoya-ship`)의 **선택지 수와 차례**를 바꾸지 않는다. 글자는 선택지의 차례 번호를 담는다.
- 1막 거점(`prologue`·`namwon`·`nanggoya`·`annam`)의 `steps` 배열은 노는 차례 그대로 둔다(목표 차례 = 단계 배열 차례, `tests/content.mjs`가 본다).
- 1막에서 게이지는 딜레마 선택지, `gauge`·`dream` 단계, 단계의 `fx`로만 바꾼다. 대사 줄의 `fx`, NPC 말, 목표의 `say`에서 게이지·조각·신표를 바꾸면 되살릴 때 빠진다.
- 1막 지식은 `card`(`history`)·`know` 단계로만 준다(`learnStep`으로 부르는 것 포함). 글자에 담긴 지식 여섯 말고 1막에 새 지식을 더하면 그 지식은 글자로 되살아나지 않는다.
- 1막에서 갈림에 따라 달라지는 단계는 단계 자체에 `when`을 단다. 목표(beat)의 `when`은 되살릴 때 보이지 않는다.
- 단계·목표 id를 바꾸면 진행 중인 저장의 `done`·`applied` 열쇠(`s:거점:단계`, `b:거점:목표`, `p:거점`)가 어긋나 그 단계가 다시 나오거나 보상이 두 번 들어간다. 이미 배포한 뒤에는 id를 바꾸지 않고 새 id를 더한다.
- 확인: 1막 자료를 고친 뒤 `node rules.mjs`(무작위 200개 왕복), `node act1.mjs`, `node code.mjs`가 통과해야 한다.

## 숫자를 바꿀 때

- 지혜의 길의 폭은 연의 길·살아남는 길의 폭보다 작게 둔다.
- 원작대로(떠남·준비) 걸으면 뱃길을 고를 때 생이 바다길 문턱 이상이어야 한다. `TEXTS.RULES`(선택지 폭·막간 생), 항주 '배와 양식 마련', `js/data/places/sea.js`의 `TUNE.seaMin`을 함께 본다. 확인: `node content.mjs`(모든 선택 조합)와 `node original.mjs`.

## 납품 조건(소재·글)

- `assets/`의 `sprites`·`sc`·`pt`·`ui`·`bgm`·`sfx`·`fonts` 아래 모든 파일은 `credits/*.tsv`에 한 줄씩 있어야 한다. 머리줄은 `파일 / 출처 / 이용 조건 / 고친 내용`(탭 구분), 출처와 고친 내용이 비어 있으면 안 되고, 없는 파일을 가리키는 줄도 안 된다.
- 이용 조건은 허용 목록 안이어야 한다: 자체 생성물·자체 제작·자체 합성, 공공누리 제1유형, CC0, CC BY(NC·ND 없는 것), SIL Open Font License, 퍼블릭 도메인. 비상업·변경금지·공공누리 제2~4유형·'불분명'은 넣지 않는다. 조건을 확인할 수 없으면 넣지 않는다.
- 「영웅의 길」 소재 파일을 그대로 가져오지 않는다. 예외는 디지털 이음(공공누리 제1유형) 배경음과 SIL OFL 글꼴뿐이다(`tests/content.mjs`가 해시로 대조).
- 위 셋은 `tests/content.mjs`(그림은 `art.mjs`, 소리는 `audio.mjs`도)가 강제한다. 소재를 더하거나 바꾸면 `credits/*.tsv` → `CREDITS.md` → `js/data/credits.js`(게임 안 출처 화면) 차례로 맞춘다. 뒤의 둘은 점검이 보지 않지만 납품 문서다.
- 그림은 Codex CLI 이미지 생성으로 만든 자체 생성물만 쓴다. 생성이 막히면 다른 이미지 도구로 몰래 바꾸지 않고 만든이에게 알린다(납품 조건과 화풍 일관성). 장면 삽화·초상·화면 그림은 고른 화풍(현대 그림책풍)으로만 그린다. 그림 안에 글자·낙관·서명을 넣지 않고, 피·주검·자해를 그리지 않는다.
- 교과서·모의평가·시중 번역서의 번역문과 풀이를 쓰지 않는다. 풀이·함정 구절·대사·카드 글은 직접 쓴다.
- 원문은 공유 저작물 판본(위키문헌 「최척전」, 규장각 원문 이미지로 판독 수정, 한국고전종합DB 「김영철전」)에서만 가져오고 출처를 적는다. 원문을 지어내지 않는다. 출처를 찾지 못한 구절은 쓰지 않는다. 귀국 항해 대목(출항~해적 직전)은 대표 이본에 없으므로 원문 없이 줄거리 요약과 이본 노트로만 다룬다.
- 원문 한문 구절은 늘 풀이와 짝으로 둔다(`{ 원문, 풀이 }`, 카드의 `han`+`ko`). 표기 구분값은 `원문`·`풀이`·`게임 설정`·`이본 노트`·`해석` 다섯 가지뿐이다(`tests/content.mjs`).
- 확정하지 못한 사실은 비워 두지 않고 가장 그럴듯한 쪽을 쓴 뒤 '⚠ 검수 필요'로 `design/research/01_원문_사실확인.md` §9와 README의 교사 검수 목록에 올린다. 역사 카드면 `review` 칸에 적는다.

## 정서 안전과 원작 줄거리

- 옥영의 자결 시도를 선택지로 만들지 않는다. 서술·삽화로만, 직접 묘사 없이, 장육불의 말을 중심에 둔다.
- 전쟁 폭력(남원 함락, 해적)은 불빛·그림자·흩어지는 소리로 상징한다. 피·주검·처형을 글이나 그림으로 보이지 않는다.
- 원작의 큰 사건(이산, 포로, 안남 재회, 두 번째 이별, 해적, 조선 배, 남원 재회)은 어떤 선택에서도 일어나게 둔다. 게임 오버와 '나쁜 결말'을 만들지 않는다.
- 게임이 지어낸 장면·딜레마는 원작 대조 카드에서 '원작에는 없는 장면'으로 밝힌다(딜레마의 `orig: null`).

## 화면 품질

- 새 화면·부품은 `design/ui/미술방향.md`를 따른다: 쪽빛 밤(`--night`) 틀 + 한지(`--hanji`) 판 + 강조색은 등불 주황(`--lantern`) 하나, 본문 HangroBatang, 제목 HangroBrush, 그림책풍 그림.
- 탐색 화면은 맵이 화면 전체를 채우고 정보는 네 구석 HUD에 얹는다. 화면을 맵/패널로 나누는 배치, 브라우저 기본 단추·회색 상자·기본 스크롤 막대, 코드로 대충 그린 지도처럼 '개발용 시험 틀'로 보이는 화면을 내보내지 않는다. 만든이가 이 모양을 거절했다.
- 가로 화면 기준이다. 세로는 안내 화면 한 장뿐이다. 휴대폰 가로 844×390과 PC 1366×860에서 HUD가 서로·맵 가장자리 사람과 겹치지 않아야 한다(`tests/smoke.mjs`).

## 글꼴

- `js/`·`css/`·`index.html`의 글을 고쳐 새 글자가 생길 수 있으면 `python tools/build_fonts.py`를 돌리고 바뀐 `assets/fonts/*.woff2`를 **같은 커밋**에 넣는다. 위반하면 새 글자만 기기 글꼴로 보인다(점검은 잡지 못한다).
- 붓글씨(`var(--brush)`)로 보일 새 제목은 `tools/build_fonts.py`의 `BRUSH_EXTRA`에 그 글자를 더하거나, 거점·맵의 `name: '…'` 꼴로 적어 도구가 찾게 한다.
- 부분 글꼴의 이름은 `HangroBatang`·`HangroHanja`·`HangroBrush`로 둔다. OFL 예약 이름(Nanum 등)을 부분 글꼴에 쓰지 않는다. `assets/fonts/OFL.txt`를 함께 배포한다.

## 커밋 전 점검

- 코드·데이터·소재를 바꾼 커밋 전에 `cd tests && npm run verify`(17개 스크립트, 45~60분)가 옵션 없이 통과해야 한다. 한 번에 **하나만**, 차례대로 돌린다. 같은 기기에서 점검을 둘 이상 겹쳐 돌리면 소리 장치·시간 초과로 거짓 실패가 난다.
- 글·숫자만 고쳤다면 빠른 점검 `node content.mjs && node smoke.mjs && node endgame.mjs && node art.mjs`로 먼저 확인하고, 커밋 묶음의 끝에서 전체 점검을 한 번 돈다.
- 콘솔 오류·페이지 오류·실패한 요청·400 이상 응답은 0건이어야 한다. 허용되는 예외는 장면을 빨리 넘길 때 끊기는 `assets/bgm/*.mp3` 받기(`ERR_ABORTED`)와 결과 그림 `blob:` 내려받기뿐이다.
- 문서(`*.md`)만 바꾼 커밋은 점검 대상이 아니다.

## 커밋

- 커밋 메시지는 한국어로, 무엇이 바뀌었는지 쉬운 말로 쓴다(예: "출처 목록이 비었을 때의 안내 글 고침"). `feat:` 같은 영어 머리말은 쓰지 않는다. 필요하면 빈 줄 뒤에 '- ' 목록으로 자세히 적는다. AI가 함께 만든 커밋은 끝에 `Co-Authored-By:` 줄을 단다.
- 저장소에 올리지 않는 것: `tests/node_modules/`, `tests/shots/`(점검 화면 사진), `assets/raw/`(이미지 생성 원본), `assets/raw_audio/`(내려받은 원음), `__pycache__/`, `*.log`, 도구 상태 폴더(`.omc`, `.claude`).
- 푸시·저장소 공개·배포는 만든이가 요청할 때만 한다.
