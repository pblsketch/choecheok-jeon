# 0008. 「영웅의 길」 엔진을 가져와 고쳐 쓴다(빌드 도구 없는 순수 JS)

- 상태: 확정(만든이 결정)

## 맥락
같은 만든이의 「영웅의 길」(`../영웅소설`)에는 이미 교실에서 쓰인 탑다운 맵(캔버스·카메라·충돌·가상 조이스틱), 대화와 단계 실행기, 저장, 국악 합성 소리, 화면 부품, Codex 이미지 파이프라인, Playwright 점검 방식이 있다. 이 게임은 2차시에 완주할 수 있는 완성판을 짧은 기간에 만들어야 하고, 시리즈 게임끼리 표기 체계·조작이 이어져야 한다.

## 결정
「영웅의 길」의 엔진 파일을 이 저장소로 **복사해 고쳐 쓴다**. 싸움·기술·적장전·카드 전투는 가져오지 않는다. 형태는 그대로 HTML + CSS + 순수 JavaScript, 빌드 도구 없음, Canvas 2D + Web Audio. 그림·소리 파일은 가져오지 않는다(예외: 이용 조건을 확인한 디지털 이음 배경음 원음, OFL 글꼴 원본). 원래 폴더는 읽기만 한다.

## 버린 안
- 새 엔진이나 게임 프레임워크(Phaser, Three.js 등): 기존 맵·대화·점검 방식을 다시 만들어야 하고, 빌드 단계가 생겨 `index.html`을 파일로 여는 교실 사용과 '어디든 올리면 도는' 배포 중립이 어려워진다. 기획안 v0의 Three.js는 버렸다.
- 두 게임이 엔진을 공유 라이브러리로 함께 쓰기: 한쪽을 고치면 다른 게임이 깨질 수 있고, 형제 저장소를 고치지 않는다는 원칙과 맞지 않는다.

## 결과
- 엔진 코드는 이 저장소 안에서 독립적으로 바뀐다. 「영웅의 길」에서 고친 버그가 저절로 들어오지 않고, 이쪽의 고침도 저쪽으로 가지 않는다.
- 「영웅의 길」 소재 파일이 섞여 들어오지 않았는지 `tests/content.mjs`가 해시로 대조하므로, 점검은 `../영웅소설/assets`가 있어야 돈다.
- 빌드 도구가 없으므로 모듈 경계는 `<script>` 차례와 전역 `G`·데이터 전역으로만 지켜진다.
