# 풀리지 않은 문제

## 「김영철전」 원문의 구두점 이용 조건이 확인되지 않았다
- 무엇: 「김영철전」 함께 읽기 단계(`js/data/kimyc.js`의 `passage.원문`, `deep.quote.원문`)와 `design/research/원문_김영철전.md`의 원문 구두점은 한국고전번역원 표점본을 따랐다. 원문 자체는 공유 저작물이지만 표점(구두점)은 DB의 편집 결과물이라 이용 조건이 따로일 수 있다.
- 영향: 납품 조건(모든 소재가 상업 납품 가능)을 확인하지 못한 유일한 글 소재다. 조건이 맞지 않으면 납품 전에 그 대목의 구두점을 새로 찍어야 한다.
- 지금 못 푸는 까닭: DB 이용 조건 확인 또는 구두점을 새로 찍을지는 만든이·출판사가 정할 일이다(README 교사 검수 목록 37번).
- 할 수 있는 방법: 한국고전종합DB 이용 약관을 확인하거나, 원문 이미지에서 직접 구두점을 찍어 `kimyc.js`와 원문 사본을 바꾼다(구두점만 바뀌므로 화면·점검에는 영향 없음, 글꼴만 다시 만든다).

## `?act=2` 주소가 학생의 진행과 이름을 확인 없이 지운다
- 무엇: 1막을 진행한 브라우저에서 `?act=2`를 붙여 열면(그 주소로 시작한 2막을 하던 중이 아니면) `G.rules.startAct2()`가 저장을 초기화해 진행과 이름이 확인 없이 사라진다.
- 영향: 선생님이 미리 보기용 주소를 학생에게 나누어 주거나 학생이 따라 하면 1차시 진행이 사라진다(이어 하기 글자를 적어 두지 않았다면 되살릴 수 없다).
- 지금 못 푸는 까닭: 설계는 `?act=2`를 '선생님 미리 보기'로만 정했고 기존 기록이 있을 때의 처리를 정하지 않았다. 확인 판을 띄울지, 선생님용일 때만 받을지는 만든이가 정할 일이다.
- 할 수 있는 방법: 저장에 진행 기록이 있으면 '처음부터'와 같은 확인 판을 띄운 뒤 지운다(`js/main.js`의 `act` 바로가기). `tests/rules.mjs`·`tests/act2.mjs`의 `?act=2` 단정도 함께 고친다.

## 점검이 「영웅의 길」 폴더가 없는 기기에서 실패한다
- 무엇: `tests/content.mjs`의 납품 점검은 `../영웅소설/assets`(또는 `HERO_ASSETS`)가 없으면 "소재 폴더를 찾을 수 없음"으로 실패하고, 그래서 `npm run verify` 전체가 멈춘다.
- 영향: 이 저장소만 받은 사람(출판사 검수 담당, 다른 개발 기기)은 전체 점검을 통과시킬 수 없다.
- 지금 못 푸는 까닭: 점검 코드를 바꾸는 일이고, 「영웅의 길」 소재가 섞이지 않았다는 확인을 건너뛰어도 되는지는 납품 조건 판단이 필요하다.
- 할 수 있는 방법: 폴더가 없으면 그 한 단정만 '건너뜀'으로 찍고 경고하는 옵션을 두거나, 「영웅의 길」 소재의 해시 목록을 이 저장소에 함께 두어 폴더 없이 대조한다.

## 규칙 숫자 파일의 `countCap` 설명이 실제 부호화와 다르다
- 무엇: `js/data/texts.js`의 `countCap: 7` 설명은 "이어 하기 글자에 담는 횟수의 끝(8 이상은 7로 담고 '7+'로 보인다)"이라고 적었지만, 실제로 글자(`js/game/code.js`)는 더듬기 0~10과 고친 횟수 0~8을 담고, `countCap`은 화면에 보이는 끝('7+')만 정한다.
- 영향: 선생님이 이 숫자를 바꾸면 글자 부호화도 바뀐다고 오해할 수 있다(실제로는 보이는 글만 바뀐다). 코드 동작에는 영향이 없다.
- 지금 못 푸는 까닭: 이 기록을 쓰는 동안 같은 폴더에서 전체 점검이 돌고 있어 `js/` 파일을 고치지 않았다.
- 할 수 있는 방법: 다음 코드 변경 때 설명을 "결과 화면·수첩에 보이는 횟수의 끝(8 이상은 '7+')"으로 고치고, 글꼴을 다시 만든다.

## 안남 예외(더듬어 찾기로 생 0)는 실제 선택으로 닿지 않는다
- 무엇: 1막의 어떤 선택 조합으로 안남에 닿아도 빈 행을 모두 더듬은 뒤 생이 1 이상 남는다. 그래서 '최척이 퉁소를 한 번 더 불어 정답이 떠오르는' 장면은 학생이 실제로 볼 수 없고, 점검(`tests/hard.mjs`)도 생을 1로 맞춰서만 확인한다.
- 영향: 설계한 장면 하나가 쓰이지 않는다. 숫자를 바꿔 닿게 되면 그때 처음 실제 흐름에서 이 장면이 나온다(점검은 이미 통과하고 있어 차이를 알려 주지 않는다).
- 지금 못 푸는 까닭: 게이지 폭·더듬기 값 조정은 실제 학생 플레이 뒤에 하기로 했다. 지금 숫자를 바꾸면 결말 분포와 원작대로 걸었을 때의 바다길 불변식까지 다시 맞춰야 한다.
- 할 수 있는 방법: 교실 플레이 뒤 1막 생 소모·더듬기 값을 조정할 때 이 장면에 닿는 길이 생기는지 `tests/content.mjs`의 선택 조합 탐색으로 함께 본다.

## 마지막 커밋들 위에서 전체 점검 결과가 기록되지 않았다
- 무엇: 마지막으로 통과가 기록된 전체 점검(2026-10-08 06:37, 종료 코드 0)은 README·출처 목록(`js/data/credits.js`)·안내 글 한 줄(`js/data/notes.js`)·부분 글꼴을 바꾼 마지막 세 커밋보다 앞선 상태에서 돌았다.
- 영향: 바뀐 것은 문서·출처 목록 자료·안내 글 한 줄·글꼴이라 깨질 가능성은 낮지만, 지금 HEAD가 점검을 통과한다는 기록은 없다.
- 지금 못 푸는 까닭: 이 기록을 쓰는 동안 같은 폴더에서 HEAD 기준 전체 점검이 돌고 있었고, 점검을 겹쳐 돌리면 거짓 실패가 나므로 따로 돌리지 않았다.
- 할 수 있는 방법: 그 점검이 끝나면 스크립트별 점검 수·문제 수를 기록하고 이 항목을 지운다.
